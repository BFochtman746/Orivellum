1. System Vision & Core Invariants
MONARCH is a lifelong autonomous knowledge construction, reasoning, engineering, and automation platform. It does not merely answer questions; it builds, validates, retains, and improves expert domains.
Non-negotiable invariants:
	•	Every claim must carry provenance + validation status.
	•	No knowledge is accepted without evidence evaluation.
	•	Every completed task becomes permanent training material.
	•	Multiple candidate solutions are generated, scored, and ranked before selection.
	•	Domains are measurable: completion score is tracked and gaps are actively closed.
	•	All workers are versioned, observable, and replaceable.
	•	The system can operate with zero human intervention after initial domain seed (sovereignty).

3. Detailed Component Design
3.1 Orchestration Layer
Orchestration Manager (OM)
Central brain. Owns the global control loop.
Responsibilities:
	•	Accept high-level goals (“Build domain X to completion score ≥ 0.85”).
	•	Decompose into task DAGs.
	•	Assign workers via capability matching.
	•	Monitor progress, health, and resource budgets.
	•	Trigger re-planning on failure or new evidence.
	•	Enforce multi-solution policy (minimum N candidates before ranking).
Task Manager
Task lifecycle (exact states from your spec, extended):
Pending → Assigned → InProgress → Blocked | Review → Completed | Rejected
Rejected → InProgress (retry with new strategy) or Failed (max retries)
Every task carries:
	•	Goal + success criteria
	•	Required capabilities
	•	Dependency list
	•	Resource budget (tokens, API calls, CPU-time, wall-time)
	•	Provenance chain
	•	Validation requirements
Worker Manager
	•	Maintains a live registry of worker instances (type, version, capabilities, current load, health).
	•	Selects workers by capability match + load + historical success rate.
	•	Supports hot-reload of new worker versions.
	•	Isolates workers (each runs in its own process/container with resource limits).
State Manager
	•	Global system state + per-session / per-domain context.
	•	Checkpointing of long-running domain builds.
	•	Context propagation (workers receive only the relevant subgraph + prior results).

	5	Generate dependency graph
	6	Create learning path
	7	Construct benchmark suite + laboratory
	8	Generate implementation examples + troubleshooting guide
	9	Build validation suite
	10	Train / refine expert reasoning model (prompt + retrieval + scoring)
	11	Identify automation opportunities
	12	Produce improvement roadmap
	13	Measure completion score → if below threshold, generate new gap-filling tasks and loop
Research Cycle (as in your diagram)
Hypothesis generation → plan → evidence gathering → evaluation → contradiction detection → methodology comparison → unknowns → experiment recommendations → synthesis → knowledge update → validation → refine or finalize.
Multi-Solution Engineering / Programming Pattern

6. Security, Safety & Sovereignty
	•	All external tool / API calls are sandboxed and budgeted.
	•	Knowledge writes require Validation Manager approval for “accepted” status.
	•	Human override channel always available (but system can run fully autonomously).
	•	Full audit log of every decision, source, and score.
	•	Worker code is versioned and signed.
	•	Resource quotas prevent runaway costs.
